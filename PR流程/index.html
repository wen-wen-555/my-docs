GitHub开源贡献入门：如何给别人的项目提交PR

本文是一篇手把手教你如何在GitHub上给别人的开源项目提交修改（Pull Request）。

什么是PR?

PR全称Pull Request ，中文叫“合并请求”。

当你想给别人的开源项目贡献代码或修改文档时，你不能直接修改别人的仓库。正确做法如下：

1.先把项目“复制”一份到自己的GitHub账号下（这个过程叫Fork）

2.在自己的副本里做修改

3.向原作者发一份“申请”，请他把你的修改合并到原项目中

这份“申请”就是PR。

完整流程（网页版）

第一步：找到目标项目

在GitHub上找到你想贡献的项目。例如本教程以bddbnet/gin_readme_zh为例。

第二步：Fork项目

进入项目页面后，点击右上角的Fork按钮。

GitHub会自动将这个项目“复印”一份到你自己的账号下。

Fork之后，你拥有这个副本的完全编辑权限，可以随意修改，不会影响原项目。

第三步：编辑文件

进入你Fork后的仓库，找到你想修改的文件（例如：README.md），点击文件右上角的铅笔图标（Edit this file），进入在线编辑模式。

第四步：修改并提交

在编辑器中完成你的修改后，滚动到页面底部：

  • 在Commit message 栏写一句简短的修改说明，例如：Add Go Modu les setup guide

  • 点击绿色的Commit changes按钮

此时，你的修改已经保存到了你自己Fork仓库中。

第五步：发起Pull Request

提交修改后，页面会自动跳转到一个对比页面（Comparing changes），显示你的修改和原项目的差异。

确认信息无误后，点击绿色的Create pull request按钮。

接下来会进入PR填写页面：

  • 标题（Title）：自动填好了你的Commit message，可以保留或修改
  • 描述（Description）：补充说明你具体改了什么，为什么这么改
  • 点击右下角的Create pull request按钮，正式提交

第六步：等待反馈

PR提交成功后，原作者会收到通知。他可能会：

  • 直接合并（Merge）:接受你的修改，你的贡献正式上线
  • 提出修改意见：在PR下方留言，请你调整某此内容
  • 关闭（Close）：不接受这次修改

即使被拒绝也不用气馁，这本身就是很好的一次学习。

注意事项

  • PR提交后不会影响原作者的项目，只有原作者同意合并后才会生效
  • 修改说明（Commit message）尽量写清楚，方便原作者快速理解你的意图
  • 如果是较大的修改，建议先在项目的lssues中和作者沟通，确认方向后再动手
  • 网页版编辑适合简单的文档修改；如果是代码级别的改动，建议用本地Git操作（clone$$\longrightarrow$$修改$$\longrightarrow$$commit$$\longrightarrow$$push）

总结

整个PR流程可以概括为以下五步：

Fork > 编辑 > Commit > 发起PR > 等待反馈

这就是GitHub开源协作最基本的方式。无论是修改文档、修复Bug还是添加新功能，任何开源项目都是通过PR来接受外部贡献的。
